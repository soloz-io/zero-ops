# GitOps Repository Example - Applicability Analysis

## Project Overview
**Source:** `.kiro/specs/agentic-enterprise-onboarding/references/redhat/gitops-repo-example/`

Red Hat's reference GitOps repository structure generated by KAM CLI. Demonstrates production-grade multi-environment Kustomize layout with ArgoCD Applications.

## Applicability to Zero-Ops Platform

### ✅ HIGHLY APPLICABLE

**Use Case:** Tenant Control Plane Repository Structure

**Justification:**
1. **Industry Standard Pattern**: Red Hat's GitOps structure is battle-tested across thousands of OpenShift deployments.
2. **Zero-Ops Requirement**: PRD Req 4 AC10-12 mandates Git repository creation with Kustomize structure for tenant control planes.
3. **Multi-Environment Support**: Pattern supports dev/staging/production overlays - maps directly to Zero-Ops starter/enterprise tiers.
4. **ArgoCD Native**: Structure optimized for ArgoCD ApplicationSet pattern (already in Zero-Ops PRD).

## Recommended Adoption

### ✅ Adopt: Repository Structure Pattern

**Red Hat Pattern:**
```
gitops-repo/
├── config/
│   └── argocd/
│       ├── dev-env-app.yaml
│       ├── stage-env-app.yaml
│       └── kustomization.yaml
├── environments/
│   ├── dev/
│   │   ├── apps/
│   │   └── env/
│   │       ├── base/
│   │       │   ├── dev-environment.yaml
│   │       │   ├── dev-rolebinding.yaml
│   │       │   └── kustomization.yaml
│   │       └── overlays/
│   └── stage/
│       ├── apps/
│       └── env/
└── pipelines.yaml
```

**Zero-Ops Adaptation:**
```
{tenant-id}-control-plane/
├── .sops.yaml                    # Age public key encryption rule
├── base/
│   ├── kustomization.yaml        # KSOPS plugin config
│   └── secrets/                  # SOPS-encrypted credentials
│       └── hetzner-token.enc.yaml
├── overlays/
│   ├── starter/
│   │   ├── kustomization.yaml
│   │   └── ainativesaas-starter.yaml
│   └── enterprise/
│       ├── kustomization.yaml
│       └── ainativesaas-enterprise.yaml
└── argocd/
    ├── starter-app.yaml          # ArgoCD Application CR
    └── enterprise-app.yaml
```

### ✅ Adopt: Base + Overlays Pattern

**Red Hat Pattern:**
- `base/`: Common resources shared across environments
- `overlays/`: Environment-specific patches (dev, stage, prod)
- Each overlay references base via `kustomization.yaml`

**Zero-Ops Mapping:**
```yaml
# overlays/enterprise/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

resources:
  - ../../base

patches:
  - path: ainativesaas-enterprise.yaml
    target:
      kind: AINativeSaaS
```

**Benefit:** Tenant can provision multiple environments (staging, production) from same base with tier-specific overlays.

**Source Reference:**

### ✅ Adopt: ArgoCD Application-per-Environment

**Red Hat Pattern:**
```yaml
# config/argocd/dev-env-app.yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: dev-environment
spec:
  source:
    path: environments/dev/env/overlays
    repoURL: https://github.com/org/gitops.git
  destination:
    namespace: dev
```

**Zero-Ops Adaptation:**
```yaml
# argocd/enterprise-app.yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: acme-corp-enterprise
  namespace: argocd-system
spec:
  project: tenant-acme-corp
  source:
    path: overlays/enterprise
    repoURL: https://github.com/zero-ops/acme-corp-control-plane.git
    targetRevision: main
  destination:
    server: https://kubernetes.default.svc
    namespace: zero-ops-tenants
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
```

**Source Reference:**
```
.kiro/specs/agentic-enterprise-onboarding/references/redhat/gitops-repo-example/config/argocd/
```

### ✅ Adopt: Namespace-per-Environment Pattern

**Red Hat Pattern:**
- `dev-environment.yaml`: Namespace CR for dev
- `stage-environment.yaml`: Namespace CR for stage
- Each environment isolated via RBAC

**Zero-Ops Adaptation:**
```yaml
# overlays/enterprise/namespace.yaml
apiVersion: v1
kind: Namespace
metadata:
  name: acme-corp-enterprise
  labels:
    nutgraf.in/tenant-id: acme-corp
    nutgraf.in/tier: enterprise
```

**Benefit:** Clear namespace isolation per tenant environment.

## Specific Patterns to Extract

### 1. Kustomization Base Template
**File:** `environments/dev/env/base/kustomization.yaml`
**Pattern:**
```yaml
resources:
  - namespace.yaml
  - rolebinding.yaml
  - ainativesaas-cr.yaml
```

**Zero-Ops Application:**
```yaml
# {tenant}-control-plane/base/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

resources:
  - secrets/

generators:
  - ksops-generator.yaml  # KSOPS plugin
```

### 2. Overlay Kustomization Template
**File:** `environments/dev/env/overlays/kustomization.yaml`
**Pattern:** References base, applies patches

**Zero-Ops Application:**
```yaml
# overlays/enterprise/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

resources:
  - ../../base

patchesStrategicMerge:
  - ainativesaas-enterprise.yaml
```

### 3. ArgoCD Application Template
**File:** `config/argocd/dev-env-app.yaml`
**Pattern:** Application CR per environment

**Zero-Ops Application:** Management cluster ArgoCD watches tenant repos via ApplicationSet.

## Risks if NOT Adopted
- Inconsistent Git repository structure across tenants
- Manual Kustomize layout creation (error-prone)
- No industry-standard reference for tenant repos
- Difficult multi-environment support (staging/production)

## Enhancements Over Red Hat Pattern

### 1. KSOPS Integration
**Red Hat Pattern:** Uses SealedSecrets
**Zero-Ops Enhancement:** KSOPS + Age (more flexible, supports multiple backends)

### 2. Crossplane XRD
**Red Hat Pattern:** Kubernetes native resources only
**Zero-Ops Enhancement:** AINativeSaaS XRD (infrastructure provisioning)

### 3. Tenant Isolation
**Red Hat Pattern:** Namespace-based
**Zero-Ops Enhancement:** Namespace (Starter) OR dedicated cluster (Enterprise)
