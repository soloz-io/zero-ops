## Key Architectural Patterns

**GitOps-First:**
- All MCP tools commit to Git (never direct kubectl apply)
- ArgoCD ApplicationSets watch fleet-registry for new tenants
- Tenant repos created from templates during onboarding

**Event-Driven:**
- Hub publishes `opensbt_onboardingRequest` → Spoke provisions
- Spoke publishes `opensbt_agentAppHealthChanged` → Hub updates status
- NATS event bus for async communication

**Hub-Spoke Communication:**
- ArgoCD agents pull from Hub (no Hub-to-Spoke connections)
- SPIFFE mTLS for spoke-to-hub authentication
- Grafana Alloy pushes metrics via webhook

**Tenant Isolation:**
- Dedicated spoke = 1 tenant, 3 AZ control plane, spread app plane
- Shared spoke = multi-tenant control plane, namespace isolation

This gives you a **single-click provisioning** experience where the AI agent orchestrates:
1. Create tenant repos (control + app plane) from templates
2. Register tenant in fleet-registry
3. ApplicationSet auto-discovers and deploys
4. Spoke agents report health back to Hub
5. Tenant transitions to READY state

All declarative, GitOps-native, with ArgoCD agents handling the heavy lifting!
