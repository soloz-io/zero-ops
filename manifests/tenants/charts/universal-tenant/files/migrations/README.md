# Tenant Baseline Migrations

This directory contains SQL migration files for tenant database initialization.

## Files

- `*.sql` - Migration files following Atlas naming convention: `YYYYMMDDHHMMSS_description.sql`
- `atlas.sum` - Checksum file generated by Atlas CLI (integrity verification)

## Atlas Checksum File

The `atlas.sum` file contains SHA256 checksums of all migration files. Atlas Operator uses this to verify migration integrity before applying them.

### Regenerating atlas.sum

After adding, modifying, or removing migration files, regenerate the checksum:

```bash
atlas migrate hash --dir file://charts/universal-tenant/files/migrations
```

This command:
1. Scans all `*.sql` files in the directory
2. Calculates SHA256 hash for each file
3. Generates/updates `atlas.sum` with checksums

### Important Notes

- **Always regenerate** `atlas.sum` after changing any SQL file
- Atlas Operator will reject migrations if checksums don't match
- The first line in `atlas.sum` is the directory hash (hash of all file hashes)
- Commit both SQL files and `atlas.sum` together in Git

## Migration Deployment

These migrations are deployed via Helm chart template:
- Template: `charts/universal-tenant/templates/configmap-migrations.yaml`
- Uses Helm `.Files.Glob` to read all `*.sql` and `atlas.sum` files
- ConfigMap created in `tenant-{tenantId}` namespace (same namespace as AtlasMigration CR)
- AtlasMigration CR references ConfigMap via `dir.configMapRef.name: tenant-baseline-migrations`

## Adding New Migrations

1. Create new SQL file: `YYYYMMDDHHMMSS_description.sql`
2. Write idempotent SQL (use `IF NOT EXISTS`, `CREATE OR REPLACE`, etc.)
3. Regenerate checksum: `atlas migrate hash --dir file://charts/universal-tenant/files/migrations`
4. Commit both files to Git
5. ArgoCD will sync and apply to all tenants
