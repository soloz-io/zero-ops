### 1. Execution Safety, Trust & Guardrails (The "Trading Floor")
*To prevent runaway costs, infinite loops, and compliance breaches.*

*   **Q1.1: What are the exact "Circuit Breakers" for agent execution?** 
    *   *Context:* Agents can get stuck in "think/act" loops or repeatedly call a failing API. 
    *   *Question:* What are the hard limits per agent execution run (e.g., max tokens, max tool invocations, max duration in seconds)? Do these limits differ between Starter and Enterprise tiers?
*   **Q1.2: How do we prevent PII leakage to external LLM providers?**
    *   *Context:* Section 7.2 states Post-LLM filtering will redact PII. However, if the LLM leaked it, the PII has *already* crossed the BYOC boundary to OpenAI/Anthropic via LiteLLM, which is a major compliance violation.
    *   *Question:* Will we implement a Pre-LLM masking/tokenization step for PII, or rely entirely on tenants not putting PII in their prompts? 
*   **Q1.3: What is the exact End-User UX when a guardrail trips?**
    *   *Context:* If an end-user asks a Spoke Business Agent a blocked question, returning a "403 Forbidden" or generic error is terrible UX.
    *   *Question:* Does the agent attempt to self-correct, gracefully refuse the prompt, or escalate to a human? How does the tenant configure this "refusal" response?

### 2. Context-as-a-Service & Data Isolation
*To maintain the strict physical isolation promise of the Enterprise BYOC tier.*

*   **Q2.1: Where does the "Context Service" compute actually run?**
    *   *Context:* Section 8.1 says the Hub parses documents and generates embeddings. If an Enterprise tenant uploads a highly confidential document, processing it in the shared Hub violates their physical BYOC isolation.
    *   *Question:* Will the Context Service run locally inside the Spoke Silo for Enterprise tenants, or are we intentionally relaxing the BYOC data isolation policy for document parsing?
*   **Q2.2: What is the data lifecycle and pruning strategy for Agent Memory?**
    *   *Context:* The PRD defines document ingestion, but not updates, deletions, or memory limits. 
    *   *Question:* If a tenant deletes a document, how are the corresponding vectors purged? Furthermore, how do we prune an agent's conversational memory over time to prevent unbounded growth and degraded search latency?
*   **Q2.3: What are the ingestion limits for Context-as-a-Service?**
    *   *Question:* What happens if a tenant uploads a 10,000-page PDF? What are the file size, token count, or rate limits for document ingestion per tier?

### 3. Outcome-Based Billing (Logical Inconsistencies)
*To prevent billing disputes and tenant churn.*

*   **Q3.1: How can the platform objectively verify a "Custom Agent Task Completed"?**
    *   *Context:* Section 10.2 prices custom tasks at $0.50. However, the platform does not know the business logic of a tenant-created agent. If an agent hallucinates a wrong answer and closes a customer support ticket, it technically "completed" the task.
    *   *Question:* How do we define a "Success Status" for custom agents? *Recommendation: Drop outcome-based billing for custom agents in v10.0 and rely purely on infrastructure/token consumption until v10.1 (Tenant-defined outcomes) is ready.*
*   **Q3.2: How do we handle the "High Consumption + Outcome" double-billing scenario?**
    *   *Context:* If a platform agent takes 50 tool-call retries (consuming massive LLM costs) to successfully merge an Autopilot PR, the tenant pays for the heavy consumption *plus* the $2.00 outcome fee. 
    *   *Question:* Is there a cap on consumption costs for platform-provided outcomes, or does the tenant bear the risk of an inefficient agent run?
*   **Q3.3: What is the dispute resolution workflow?**
    *   *Question:* If a tenant is billed $5.00 for a Provisioning Task, but claims the agent provisioned the wrong size database, how is that refund/dispute handled in the platform?

### 4. Multi-Tenant Scale & Noisy Neighbors
*To protect shared resources in the Spoke Pool.*

*   **Q4.1: How are inbound requests to Spoke Business Agents throttled?**
    *   *Context:* Spoke Business Agents face the public internet. A DDoS attack or viral spike on one tenant's agent could drain the shared Spoke Pool's pgvector DB or LiteLLM quotas.
    *   *Question:* What are the exact inbound rate-limiting mechanisms (e.g., requests per minute) for Spoke Business Agents on the Starter tier?
*   **Q4.2: How do we prevent agents from DDoS-ing tenant APIs (Outbound limits)?**
    *   *Context:* An agent in a loop could hammer a tenant's internal CRM API 1,000 times a minute.
    *   *Question:* How do tenants configure outbound rate limits for the tools/APIs they provide to their agents?

### 5. Developer Experience, Testing & Integration (The "Research Lab")
*To ensure tenants can safely iterate on their AI agents.*

*   **Q5.1: How do tenants test agent changes before exposing them to end-users?**
    *   *Context:* Section 11.1 implies tenants create an agent, test it in the console, and push it live. In reality, tweaking a system prompt or guardrail requires testing against past conversations (evals) to ensure no behavioral regression.
    *   *Question:* Will agents have a "Draft" vs. "Published" state? Will there be an "Agent Evaluation/Testing" environment, or do tenants test in production?
*   **Q5.2: What is the exact protocol for custom tool integration?**
    *   *Context:* Section 1 states MCP is restricted to "platform operations only." Yet, Section 5.1 says tenants can select "Tool/API access." 
    *   *Question:* If we are not using MCP for tenant-to-tool connections, what protocol are we using? Are we expecting the platform team to build custom API wrappers for every external SaaS tool (Salesforce, Zendesk, etc.)? *Recommendation: Expand MCP to serve as the standard integration layer for Tenant Business Agents as well.*

### 6. Edge Cases & Error Handling
*   **Q6.1: What is the fallback if the Agent Debugging Service fails?**
    *   *Context:* Section 9.3 uses an LLM to debug Semantic Failures. 
    *   *Question:* What happens if the Debugging LLM itself hallucinates or goes down?
*   **Q6.2: How does the system handle upstream LLM outages?**
    *   *Context:* OpenAI or Anthropic goes down. 
    *   *Question:* Does LiteLLM automatically fall back to a different provider? If so, how does this impact tenant billing (since different models cost different amounts), and how is the tenant notified of the degraded state?
